# Architectural Decision Records (ADRs)

## ADR-001: 移动端技术栈选型 (React Native + Expo + TypeScript)
- **状态**: Accepted
- **背景**: 项目需要打造体验媲美微信的 Web3 移动应用，要求具备高性能原生渲染、极速热重载、完善的跨平台生态与强类型安全保证。
- **决策**: 采用 Expo SDK 与 React Native (TypeScript)。统一使用 `pnpm` 管理依赖。
- **后果**: 具备卓越的移动开发效率、开箱即用的安全存储、WebView 与加密原语支持。

## ADR-002: 严格统一 EVM 底层库为 `evm-call`
- **状态**: Accepted
- **背景**: 移动端 App 需要与 BSC Testnet 及未来多链进行高频 RPC 交互（余额查询、Multicall3 批量调用、Gas 估算、交易广播等）。市面上的重型库容易导致包体积膨胀、缺乏节点负载均衡。
- **决策**: 严格遵守项目原则，所有 EVM / Web3 交互统一使用 `/ssd0/git/evm-call`。
- **后果**: 零冗余依赖，具备多节点自动故障避退、阶梯式冷却重试、Multicall3 批量代币高压缩读取能力。

## ADR-003: 离线优先 (Local-First) 与低频周期同步
- **状态**: Accepted
- **背景**: 去中心化通信不需要也不应强依赖高频长连接 WebSocket 心跳。用户经常面临移动网络弱网或断网情况。
- **决策**: 消息优先写入客户端本地数据库，秒级上屏呈现。后台通过低频轮询（周期性增量拉取 `/sync?since=<timestamp>`）与 `web3-chat-worker` 交互，维持轻状态节点架构。
- **后果**: 弱网体验优异，大幅降低服务器连接负载与移动端耗电量。

## ADR-004: 链上主权社交图谱与双向好友认证
- **状态**: Accepted
- **背景**: 传统 IM 将用户好友列表保存在中心化服务器中。Web3 Chat 要求用户的身份、关系与群组成员资格具备去中心化所有权。
- **决策**: 基于 `/ssd0/git/web3-chat-contract` 的 `ChatStorageFactory` 与 `RelationshipManager` 合约实现双向链上好友确认与群组权限管理。
- **后果**: 社交关系抗审查、跨客户端互通；客户端结合本地缓存避免不必要的链上重复查询。

## ADR-005: 常数复杂度 Merkle 红包体系 (`LuckyDrop`)
- **状态**: Accepted
- **背景**: 发送多人红包时，如果在链上循环写入上百名接收方地址，会导致高额 Gas 消耗。
- **决策**: 采用 `/ssd0/git/LuckyDrop` 协议。发包方链下构建 Merkle 树，链上仅需提交一次 Merkle Root 与锁定代币（$O(1)$ 常数级 Gas）；抢红包者带 Merkle Proof 提交 Claim。
- **后果**: 红包无论发给 1 个人还是 500 个人，发包成本完全恒定，完美支持群聊红包。

## ADR-006: 钱包私钥本地隔离与非托管安全模型
- **状态**: Accepted
- **背景**: Web3 移动端私钥资产安全是核心生命线。
- **决策**: 钱包助记词与私钥采用行业标准 BIP-39 / BIP-44 规范在设备本地派生，保存在安全硬件受保护的存储区（SecureStore），任何网络请求均不携带明文私钥。
- **后果**: 彻底杜绝中心化泄露风险，保障用户资产自托管。
